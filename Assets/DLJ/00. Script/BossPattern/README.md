# 보스 패턴 매니저 사용법

## 실행 흐름

`플레이어 행동 완료 → EnemyTurn → Bosses의 다음 SO 선택 → 영역 크기 적용 → 프리팹 생성 → Patton() 1회 실행 → 패턴 종료 → PlusyTurn`

- `Bosses`의 위에서 아래 순서로 적 턴마다 하나씩 실행해.
- `[A, B, C]`라면 적 턴마다 `A → B → C → A → …` 순서야.
- 프리팹을 생성한 다음 프레임에 `Patton()`을 호출해. 전투 영역이 열리는 연출이 끝날 때까지 기다리지는 않아.
- SO 자체는 실행 중에 수정하지 않아. 같은 SO를 여러 칸에 넣어도 돼.
- 실행 순서는 씬을 새로 시작하면 첫 번째로 돌아가고, 매니저를 껐다 켜면 다음 순서를 유지해.

## 인스펙터 설정

1. 빈 게임 오브젝트의 루트에 `AbstractPatton`을 상속한 패턴 컴포넌트를 붙이고 **프리팹 에셋**으로 저장해. 루트 오브젝트와 패턴 컴포넌트는 활성화 상태여야 해.
2. Project 창에서 **Create → Scriptable Objects → BossPatternSO**로 패턴마다 SO를 만들어.
3. SO의 값을 설정해.

   | 항목 | 설정 |
   | --- | --- |
   | Pattern Prefab | 1번에서 만든 프리팹 에셋. 씬 오브젝트를 넣는 칸은 아니야. |
   | Area Size | 전투 UI의 `RectTransform.sizeDelta`. 예: `(600, 300)`. 어느 한 축이라도 0이면 기존 크기를 유지해. |
   | Duration | `Patton()` 호출 후 패턴을 유지할 시간(초). 기본값은 5초, 0이면 직접 종료해야 해. |

4. 씬의 항상 활성화된 오브젝트에 **BossPattonManger**를 붙여. 기존 클래스 이름은 유지했어.
5. 매니저의 **Bosses** 목록에 SO를 원하는 순서대로 넣어.
6. 영역 크기를 바꾸려면 매니저의 **Ingame Opening**에 해당 씬의 `IngameOpening` 컴포넌트를 연결해.
7. **Pattern Parent**는 선택 사항이야. 지정하면 패턴이 그 Transform 아래에 생성되고 프리팹의 로컬 위치를 사용해. 비우면 씬 루트에 생성해.
8. 씬에 활성화된 `TurnManager`가 하나 있어야 해. 평소처럼 플레이어 둘의 행동을 선택하고 실행하면 적 턴에 패턴이 시작돼.

매니저와 `IngameOpening`은 전투 UI를 숨길 때 함께 비활성화되는 오브젝트 아래에 두지 마. 기존 `BossPatternSO.asset`은 프리팹이 비어 있으니 연결해야 해. SO가 비어 있거나 프리팹이 없으면 경고를 남기고 해당 적 턴을 건너뛰어.

## 패턴 스크립트 작성

공격을 시작하는 코드는 `public override void Patton()`에 넣어. 매니저가 적 턴마다 새 인스턴스를 만들고 한 번 호출해. 초기 참조는 `Awake()`에서 준비하면 돼.

`Duration > 0`이면 시간이 지나면 자동으로 패턴 오브젝트를 제거하고 플레이어 턴으로 돌아가. 조건을 만족했을 때 일찍 끝내거나 `Duration = 0`을 쓰려면 **그 패턴 인스턴스 안에서** 이렇게 호출해.

```csharp
BossPattonManger.instance.CompleteCurrentPattern(this);
```

이 메서드는 `this`가 현재 실행 중인 패턴일 때만 종료해. 이전 패턴의 늦은 콜백이 새 패턴을 끝내는 걸 막아줘. `CompleteAction()`은 플레이어 행동 완료용이니 보스 패턴 종료에 사용하지 마.

생성한 탄환이나 경고 표시도 패턴 오브젝트의 자식으로 두면 종료할 때 함께 제거돼.

```csharp
Instantiate(bulletPrefab, spawn.position, spawn.rotation, transform);
```

씬 루트나 다른 부모에 생성한 오브젝트, DOTween 트윈, 외부 이벤트 구독은 해당 패턴의 `OnDisable` 등에서 직접 정리해야 해.

## 기존 패턴을 연결할 때

- `AbstractPatton` 자체는 그대로 사용해. 기존 BK의 `BosspattonSO`는 새 매니저에서 사용하지 않아.
- `Lightning`은 아직 공격 구현이 없는 빈 스크립트야. 프리팹에 넣어도 공격은 발생하지 않아.
- 기존 `QuizPatton`은 `Start()`에서 패턴을 직접 실행하고 `OnEnable()`에서도 턴 이벤트를 구독해. 그대로 프리팹에 넣으면 중복 실행과 구독 누수가 생겨. 새 방식으로 옮길 때 자동 실행/자체 턴 구독을 제거하고 공격 시작을 `Patton()` 한 곳으로 모아야 해.
- 기존 씬에 남은 자체 실행 패턴도 별도로 실행될 수 있어. 매니저로 전환할 패턴의 씬 인스턴스는 비활성화하고 프리팹만 SO에 연결해.
- 프리팹은 씬의 UI나 보스 오브젝트를 직접 저장해서 참조할 수 없어. 그런 참조가 필요한 기존 패턴은 런타임에 참조를 전달하는 작업도 필요해.
